# 史莱姆竞速实验室（联网版）

仅供本机使用的联网开发版本，基于同一套 JavaScript 模拟核心生成 macOS、Windows 和 Android App。四只史莱姆以绿、蓝、红、黄四个无碰撞点呈现。

本版本保留离线版全部功能，可同步用户自己的实盘数据，并在用户逐笔核对、二次确认后远程下注或领取奖励。日常助手会低频读取进度和题目，为站点所有者提供单次自动复述、自动完成 100 次点击、自动提交 60.00 秒报时，以及独立的 ±0.20 秒随机误差测试；躲避游戏保持官方页面原有流程。联网版不保存其他玩家 ID，只同步到指定的 GitHub private 仓库，不进入公共离线仓库。凭据仅放在权限为 `600` 的 `.env.slime-race.local`，该文件不会进入应用安装包或 Git 提交。详细规则见 [VARIANT.md](VARIANT.md)。

## 已实现规则

- 两圈比赛，中心线单圈默认按完赛时间反推为 2000 距离单位。
- 起跑速度为基础速度的 0.8～1.2 倍。
- 首次事件约等待 5 秒，之后事件结束即进行下一次判断。
- 每次事件：15% 绊倒、15% 疾冲、70% 正常，持续 1～1.5 秒。
- 每 50 ms 更新一次，当前速度每帧向目标速度趋近 10%。
- 宽赛道和内外圈路径成本；默认全宽约等于 1 秒移动距离。
- 每半圈进入弯道时可能选择新的横向目标，四个点之间没有碰撞。
- 相同随机种子在三个平台产生相同赛果。
- 可视化单场比赛、实盘历史胜率、赛前双选建议和最多 50000 场蒙特卡洛模拟。
- 累计胜场以联网同步为唯一权威来源；每次同步只把四项最新胜场、最近冠军、最新场次号和同步时间保存为本地紧凑快照，离线启动时读取该缓存，模拟盘不会计入实盘。
- 可导入当前四只史莱姆的实盘押注池，并按“追历史热门、追高赔率冷门、混合群体、均匀分散”四种公众行为预测封盘池。
- 可选择“最大期望、单场胜率优先、均衡风险、本金保护、高赔率价值”五种个人策略；所有策略仍要求正增量期望，不会只因胜率或倍数高而盲目下注。
- 本金保护策略按用户设置的最大本金亏损比例限制累计投入。由于整场最多双押，它不能对四种冠军结果同时保证零亏损；若要求所有赛果绝对保本，唯一方案是不下注。
- 支持手动填写本场已提交下注；联网完整同步时会自动识别当前盘口的个人仓位。旧下注视为不可撤回，只比较追加前后 `EV(现有 + 追加) - EV(现有)`。
- 推荐计算会考虑自己的追加同时增加总奖池和对应史莱姆押注，从而压低自身封盘赔率；累计最多选择两只，没有正增量期望时建议等待或停止追加。
- 可在 App 内使用用户自己的账号登录固定实盘站点；本地 Electron 开发版启动时会优先从权限为 `600` 的 `.env.slime-race.local` 自动登录，账号密码只由主进程读取。
- 当前比赛、账户碎片、待领取奖励、累计胜场和四只史莱姆聚合盘口默认每 4 秒自动刷新，最近场次与个人统计每 40 秒刷新；自动实时更新可随时关闭。
- 复述输入、手动点击、下注编辑、下注核对和所有远程提交期间会暂停自动刷新，避免碎片、奖励或盘口更新干扰当前操作；手动全量同步仍可使用。
- 远程下注最小 1 碎片；提交前重新校验余额、封盘状态和最多双押，之后必须二次确认。超时只同步核对，不自动重试。
- “按最优建议一键下注”优先复用最近 5 秒内的建议；建议过期时只并发刷新当前场次、聚合盘口和余额。每笔提交前后仍用同一轻量快照重新校验，双押继续串行且任一失败立即停止。
- 实时快照只重算当前主推荐；三种封盘情景稳健性留给全量同步或手动“重新计算”，避免轮询时反复阻塞界面。
- 待领取奖励按笔展示，每笔都需用户确认后调用固定赌马奖励接口，不提供自动领取。
- 日常助手低频读取复述、点击、躲避和报时四类任务进度；可手动提交复述，也可将当前服务器题目自动复述一次。
- 点击任务保留手动点击，也可显式自动完成一轮 100 次；每次操作只提交一轮，不会在后台无限循环。
- 报时任务可自动提交一次 60.00 秒结果；也可显式执行一次随机误差测试，从 59.80～60.20 秒的百分之一秒档位中随机取值，并显示提交值、绝对误差和服务端判定。躲避游戏及其成绩提交保持原官方页面流程，不在 App 内自动化。
- 躲避和报时待领奖励仍会在领取前重新核对进度，并要求用户确认；POST 失败或超时不会自动重试。
- 勇者面板可读取六只常规怪物的当前半级属性，按当前能力点、装备、四种主动技能和可选的 30 层防御药水计算“最少掉血、最快速度、均衡”三类推荐；自动循环每胜一场都会读取新的 `Lv.+0.5` 面板并重新计算、配点和更换技能。
- 自动刷怪只在用户明确确认后串行运行；升级新增的未分配能力点会自动并入下一轮最优方案。可恢复异常会在 5、10、15 秒后最多重试 3 次，战斗结果不确定时先同步次数和怪物等级对账，不会重复提交结算；预测胜率低于停止线、勇者 HP 归零、战败、药水不足或药效到期等业务停机不会重试。
- 可选在勇者 HP 低于 20% 时使用 2%、20% 或 100% 恢复药水的最省有效组合，恢复到至少 95%；达到 60 次后通过官方九宫格字母点击验证手动解除限制，验证不会自动代答。
- 本地逐场监控只记录聚合池、自己的仓位、余额和比赛状态，拟合公众追热门/追高赔率倾向，并分析个人组合在三种封盘情景下的稳健性。
- 逐笔盘口会立即按史莱姆聚合，其他玩家 ID 不进入界面、本地存储或日志；联网功能不会执行开赛、奖金注入、重置或管理操作。

路径选择属于估算项，因为当前没有原游戏的转向算法。界面中可以调整赛道宽度、弯道换道概率和横穿赛道时间，并用实测胜率与完赛时间校准。

## 打开联网版

首次运行需要在终端安装依赖：

```bash
cd /Users/marisa/slime-race-simulator
npm install
```

以后每次打开只需：

```bash
cd /Users/marisa/slime-race-simulator
npm start
```

应用窗口打开后，本地 Electron 开发版会自动使用 `.env.slime-race.local` 中的固定测试账号登录。凭据不会进入渲染层、输入框或日志；环境文件缺失或自动登录失败时会回退到手动登录。点击“退出当前账号”会停止轮询、清除本地会话并恢复手动登录，本次窗口会话内不会再次自动登录；重新启动应用后仍会按环境文件自动登录。远程下注与领取继续要求用户确认。

联网版源码和安装产物只发布到指定的 GitHub private 仓库。公共 GitHub 仓库仍只包含严格隔离的离线版。

## 本地检查

运行检查：

```bash
npm run check
```

使用环境文件中的本地测试账号执行一次真实随机报时测试：

```bash
npm run test:timer-error
```

该命令会真实提交一次报时，并可能增加测试账号的报时进度或待领奖励；不会输出账号、密码或 Cookie，也不会自动重试 POST。

## 勇者最优配点与自动刷怪

登录后点击“刷新六只方案”，软件会只读同步勇者面板、普通技能和六只常规怪物当前属性，并分别给出 HP、ATK、DEF、SPD 配点及推荐主动技能。所有模式都先选择预测胜率最高的候选，再按目标细分：

- “最少掉血”：平均掉血占每场战斗起始 HP 的百分比更低，随后比较余血比例和时间；
- “最快速度”：获胜样本的平均战斗时间更短，随后比较余血比例；
- “均衡”：把候选方案的余血比例和速度分别归一化后各占 50%。

启用主动技能优化时，护盾、吸血、虚弱和速度激发中所有已解锁技能都会与每个配点候选共同模拟；应用配点后，如果推荐技能与当前技能不同，会通过官方技能装备接口更换并重新同步验证。关闭该开关则保持当前主动技能。结果来自固定随机种子的多轮本地模拟，便于同一面板复核；它不是必胜承诺，实际挑战仍使用一轮独立随机结果。

选择怪物、本轮最多胜场和最低预测胜率后，点击“开始自动循环”并确认。每轮固定执行：

```text
读取当前怪物面板
→ 计算当前等级的推荐配点
→ HP低于20%时使用恢复药水补到至少95%
→ 把升级未分配点并入方案，再次核对面板并回收/分配能力点、更换主动技能
→ 核对最终配点、技能、药水、HP 和今日次数
→ 挑战一次并只提交一次结算
→ 验证战斗次数增加 1，胜利时怪物等级精确增加 0.5
→ 读取新面板并进入下一轮
```

“完成当前步骤后停止”不会中断已经在途的提交，而是在当前请求明确完成后退出，避免把未知结果再次提交。每天最多挑战 60 次；本轮上限会自动受今日剩余次数约束。战败会如实结算并立即停止。

网络、超时或面板并发变化等可恢复异常会按 5 秒、10 秒、15 秒递增等待，最多重试 3 次。每次重试都从重新同步开始；如果上一场战斗可能已经提交，则先用今日战斗次数和怪物等级变化判断胜败，确认未结算才重新执行本轮，因此不会盲目重复发送战斗结算。低胜率、真实败北、达到次数上限、药水不足、药效到期、无效设置及不支持的转生技能属于明确业务停机，不进入重试。

启用自动恢复后，只有当前 HP 严格低于最大 HP 的 20% 才会触发；20%–95% 之间不会消耗恢复药水。触发后会在背包内组合 2%、20% 和 100% 药水，先选择刚好覆盖 95% 目标的最小恢复量，同等恢复量时再选择消耗瓶数更少的方案。使用完成后必须同步确认实际 HP 已达到 95%，否则立即停止且不会自动追加使用。

战斗次数达到 60 后，自动循环按当前上限结束。点击“点击解锁 60 次限制”会读取官方 `/api/hero/unlock-challenge` 九宫格题目；用户人工查看并点击对应的两个字母后，软件只向 `/api/hero/unlock-exp` 提交一次。验证成功且战斗次数确实解除后，才可重新启动下一轮。选择错误时只刷新题目，不会自动猜测或连续提交。

勾选防御药水后，开始时只补足到 30 层，每层按 `+100 DEF` 参与计算，单轮最多消耗 30 瓶。10 分钟药效到期或层数不再为 30 时立即停机，本轮不会再次自动用药。不勾选时按服务器当前已有层数计算且不会额外消耗药水。

当前模型覆盖六只常规怪物、已装备主动普通技能以及闪避、暴击、虚弱、吸血、护盾和速度等普通技能。若检测到已装备并激活的转生技能，自动战斗会安全停止，因为转生技能尚未纳入精确模拟。自动循环期间，比赛实时同步、下注和其他远程操作会暂停；躲避游戏逻辑及成绩提交不受此功能影响。

## 本地逐场比赛档案

联网版通过服务端只读接口 `/api/slime-race/sessions` 和 `/api/slime-race/racers` 获取最近场次、随机种子和史莱姆参数。服务端没有单独返回四只史莱姆完整名次的详情接口；官方网页同样使用场次 `seed` 在本地确定性重放。档案模块复用这套 50 ms 步进算法，只为已经结束的比赛重建完整名次、个人完赛时间、首圈顺序与时间、各名次停留时间、急冲/绊倒按名次计数和关键超越次数。正在下注、倒计时或比赛中的场次不会被提前重放。

Electron 本地版复用现有登录、实时、下注和全量同步返回的数据，在不增加网络请求的前提下捕获盘口；完成场次按 `sessionId` 增量归档并去重。开发环境的文件位于 `.local-data/race-archive/`，该目录已被 Git 忽略且不会进入安装包：

- `slime-race-archive.json`：紧凑结构化记录，包括服务端权威字段、重放聚合指标、盘口和校验结果；
- `slime-race-archive.csv`：每场每只史莱姆一行，适合电子表格和统计程序；
- `slime-race-archive.md`：适合直接阅读的逐场名次摘要；
- `slime-race-pool-state.json`：最近场次的临时聚合盘口状态，用于比赛结束后并入正式档案。

每场盘口最多保留 24 个检查点，包括最早捕获值、最新捕获值、奖池、女巫加成和当前测试账号按史莱姆聚合的仓位。档案不会保存完整事件时间线、每秒轨迹、原始逐笔下注、`betId` 或其他玩家 ID；因为保留了 `seed`、算法版本和史莱姆速度，未来需要时仍可重新生成完整轨迹。盘口状态最多保留最近 100 个场次。

也可以不打开 Electron，手动执行一次只读增量更新：

```bash
npm run archive:update
```

界面中的“打开本地比赛档案”按钮可直接打开文件夹。档案不保存账号、密码、Cookie、Token、下注用户 ID 或其他玩家身份。服务端 `totalDurationMs` 是权威总时长；每只史莱姆的单独完赛时间是官方种子算法按 50 ms 步长重放并对终点穿越时刻插值得到的估算值，JSON 中会同时保存来源和一致性校验。自动同步开关关闭时不会为档案发起额外更新；日常任务和下注期间也继续沿用现有的自动同步暂停机制。

## 打包与产物

macOS：

```bash
npm run dist:mac
```

产物位于 `release/`：

- `史莱姆竞速实验室（联网版）-1.1.2-arm64.dmg`
- `史莱姆竞速实验室（联网版）-1.1.2-arm64-mac.zip`

当前本地包没有 Apple Developer ID 签名。在其他 Mac 首次打开时可能需要右键应用并选择“打开”。

Windows（推荐在 Windows 环境执行）：

```bash
npm run dist:win
```

生成 x64 NSIS 安装器与免安装便携版：

- `史莱姆竞速实验室（联网版） Setup 1.1.2.exe`
- `史莱姆竞速实验室（联网版） 1.1.2.exe`

Android 需要 JDK 21 和 Android SDK 35：

```bash
npm run android:sync
npm run android:open
```

也可以直接构建调试 APK：

```bash
npm run android:apk
```

Android 调试 APK 默认位于 `android/app/build/outputs/apk/debug/app-debug.apk`。当前已验收的易识别副本位于：

- `release/slime-race-lab-online-1.1.3-android-debug.apk`

该 APK 使用 Android 调试证书签名，可以直接侧载安装，但不能直接提交应用商店；正式上架需要创建私有发布密钥并生成签名的 release AAB/APK。
联网版 Android 清单只申请网络权限。调试 APK 只发布到指定的 private 仓库 Release，不发布到公共离线仓库或应用商店。

在受限网络环境下，如果 Electron 运行时已经提前解压，可以分别使用 `npm run dist:mac:offline` 和 `npm run dist:win:offline`。
