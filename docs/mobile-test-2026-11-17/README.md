环境：macOS arm64 主机，Android Emulator API 35 arm64 / Pixel 7，1080×2400、density 420，对应 412 CSS 像素。使用联网版 1.2.6 的 debug APK 登录真实账号；release APK 使用相同前端资源，另行校验稳定签名和打包内容。未使用手机实体设备。

## 单只恐怖之森怪物

每组选择单一路线、最低掉血、10 胜目标、95% 最低预测胜率，允许优化主动技能与魔女技能。自动回复药水关闭，防御药水关闭。耗时为点击开始到第 10 次结算和服务端面板核对完成的墙钟时间，包含启动检查、确认框、搜索配点、网络和结算延迟；不是本地模拟中的战斗秒数。不同怪物、等级、起始血量与网络状态不同，不能把下表直接作为版本间对照。

各组 JSON 保存开始和完成时间、逐场日志、HTTP 状态与耗时，以及允许记录的结算字段。没有保存凭据、Cookie、Token 或其他玩家标识。愤怒灌木和自行人偶在省去无变更配点操作前测试；自然石像和森林狼在此优化后测试。自然石像首场之后约 12～13 秒结算一次，森林狼约 14～22 秒；仍保留战前新鲜面板核对、结算后等级 +0.5 和次数 +1 核对。

未完成记录明确保留：`forest-interrupted-baseline.json` 是调整模拟器显示参数造成的 4 场中断；`forest-mushroom_maiden-preflight-skill-error.json` 是技能切换前守卫错误，0 场提交，现已修复；`forest-mushroom_maiden-limit-6.json` 是 60 次上限截断，并包含测试确认框额外等待，不能替代 10 场计时。

## 塔、副本、布局和日常接口

- APK 无尽之塔：完整挑战 1～5 层共 15 场胜利，阶段配点纳入全部能力点，`POST /api/tower/save` 保存第 5 层返回 200，后续读取确认；账号原有最高 155 层未改变，没有领取塔奖励。这不是 155 层以上的通关测试，详见 `apk-tower-api.json`。
- 恐怖之森副本：完成两轮共 6 场胜利，每场结算 HP 683；两个宝箱均领取成功，第一轮开箱后自动进入第二轮。第二轮最后一场结算请求在途时发起安全停止，等待结算及阶段推进到 4 后停止，再领取最后一个宝箱。最终副本计数 2/10、无活动副本，常规刷怪计数仍为 60/60。配点按当天 10 轮共 30 场统一规划（生命 0／攻击 1985／防御 0／速度 1985，24 次样本预测完成率 100%），实测只执行两轮，未声称当天 10 轮全部实测完成。详见 `apk-dungeon-api.json`。
- 412 CSS 像素布局：页面 scrollWidth=412，装备、饰品、塔、副本卡片均无横向溢出；强化守护符复选框为 16×16，详见 `apk-layout-412.json`。没有把 360 像素检查记作通过。
- 当前账号无有效魔女祝福。实测 `POST /api/quest/complete-basic-with-blessing` 返回 403：`需要有效的魔女祝福才能一键完成`。此接口只覆盖基础复述/点击，不代表所有日常小游戏。详见 `blessing-basic-quest.json`。
- 官方 Android Chrome 中，森林狼 Lv194、自然石像 Lv246.5、魅惑菇娘 Lv194、陨星虫群 Lv194 各完成过一次胜利，证据为对应 txt/png；这些单场不替代上述 APK 10 场测试。此前单独使用过一瓶账号已有的 100% HP 药水，发生在本轮关闭喝药的基准测试之前。
